## Migração do front para React via Inertia (branch migracao-react) — Fase 0 e Fase 1 (INFRA)

### Atenção do Lucas: CLAUDE.md e documentação precisam ser atualizados por você
- O CLAUDE.md ainda diz "100% PHP/Laravel (Blade, Tailwind, JS vanilla)" e a Documentação 1.2 descreve o front em Blade. O Lucas autorizou explicitamente (18/11) a mudança de arquitetura para React via Inertia, dentro do Laravel. Por ordem dele, **não editei o CLAUDE.md nem a documentação/Notion**. Falta atualizar: a linha de Stack, a variável `SENTINEL_FRONT` e a convivência Blade × React.

### Decisões
- **Inertia 3.7 + React 19 + `@vitejs/plugin-react`**, instalados como pedido. Sem TypeScript, sem SSR, sem biblioteca de UI.
- **`SENTINEL_FRONT=blade|react`** (padrão `blade`), em `config/sentinel.php` (`front`) e no `.env.example`. Qualquer valor diferente de `react` vale `blade` (falha fechado para o modo atual). Helper `App\Support\Front` (`react()` e `tela($view, $pagina, $dados)`), para os controllers migrados escolherem entre `view()` e `Inertia::render()`.
- **Template raiz novo `resources/views/inertia.blade.php`** (nenhuma view existente foi editada). Copia o `<head>` do `layouts/app` (csrf, manifest, `sw.js`, tamanho do texto no `localStorage`), para o PWA e a preferência de texto valerem nos dois modos.
- **`HandleInertiaRequests` só nas rotas React** (não entrou no grupo `web`), então as telas Blade não passam por ele. Compartilha `usuario`, `menu` (mesmas regras de RBAC do layout), `flash` e `appNome`.
  - Risco: a lógica do menu está **duplicada** entre `layouts/app.blade.php` e o middleware (não pude mexer no Blade). Se o Lucas mudar o menu no Blade, tem de repetir no middleware. Corrigir na fase de CRUD, quando o menu virar fonte única.
- **Links do menu são `<a>` comuns** (carga completa), não `<Link>` do Inertia: as telas de destino ainda são Blade, e o Inertia mostraria resposta não-Inertia em modal. Trocar por `<Link>` tela a tela, conforme migrarem.
- **Layout `Layouts/Workspace.jsx`** espelha o Blade (mesmas classes de `workspace.css`, sem CSS novo) e reescreve o `workspace.js` em React: menu móvel com `inert`, foco preso, Esc, backdrop e tamanho do texto 1/2/3. O CSS do workspace é carregado pelo template raiz, sem duplicar.
- **Página de teste `GET /react-teste`** (`auth`): 404 com `SENTINEL_FRONT=blade`.
- **PWA intocado**: `manifest.webmanifest` e `sw.js` não mudaram. O service worker já guarda `/build/assets/*` e deixa páginas e JSON sempre na rede, o que serve aos dois modos.

### Descartado
- Colocar o middleware Inertia no grupo `web` (mudaria o modo Blade sem necessidade).
- Extrair o menu para uma classe compartilhada (exigiria editar o `layouts/app.blade.php`, que está fora do escopo).
- `<Link>` do Inertia no menu (ver acima).
