# Contrato do B2 (front) — Confirmar em um passo, prévia e plano_ref

Feito em 24/11. Os JSONs abaixo foram **extraídos de execuções reais** (teste temporário que despejou as respostas do servidor, já apagado), com ids e uuids encurtados. Quando algo não foi executado, está marcado como **(suposição)** ou **(do código)**.

Rotas (todas atrás de `auth`): `POST /agente/comando`, `POST /agente/revisar?previa=1`, `POST /agente/confirmar`, `POST /agente/cancelar`.
O contrato antigo `{token}` continua aceito em `/agente/confirmar` (dívida técnica; o B2 não deve usá-lo).

## 1. Abertura do card — `POST /agente/comando` (já existe)

Resposta (200), para uma tool de escrita:

```json
{
  "tipo": "confirmacao_pendente",
  "tool": "criar_lancamento",
  "risco": "escrita",
  "segurar": false,
  "segurar_quando": null,
  "argumentos": { "descricao": "Café", "valor": 12.5, "data": "2026-09-21" },
  "formulario": { "titulo": "Criar lançamento", "campos": [ { "nome": "descricao", "rotulo": "Descrição", "tipo": "texto", "obrigatorio": true, "faltando": false, "sensivel": false, "valor": "Café", "max": 255 } ] },
  "proposta": "c7d81017-…"
}
```

- `proposta` é o uuid que o front guarda e devolve nas chamadas seguintes. Vale 5 min.
- **Campos novos (23/11):** `segurar` (boolean) e `segurar_quando` (`null` ou `{campo, valor}`). Em `estornar_cobranca` o exemplo real traz `"risco": "exclusao", "segurar": true, "segurar_quando": null`.
- `segurar_quando` hoje só existe para `alterar_status_agendamento`: `{"campo": "novo_status", "valor": "cancelado"}` (coberto por `test_a_proposta_ja_abre_com_segurar_e_a_condicao_quando_depende_de_campo`). Significa: segurar só quando o campo `campo` estiver com o `valor`.
- O mesmo par `segurar`/`segurar_quando` vem em `/agente/formulario`, na prévia e nas recusas 422.

## 2. Prévia — `POST /agente/revisar?previa=1`

Chamar com debounce enquanto o usuário edita. Balde próprio: 30/min por usuário (`agente-sem-ia`, chave `previa:<user>`); estoura em 429 `AI_RATE_LIMIT`.

Requisição:

```json
{ "proposta": "c7d81017-…", "valores": { "descricao": "Café" } }
```

Resposta (200), lançamento (real):

```json
{ "tipo": "previa", "proposta": "c7d81017-…", "risco": "escrita", "segurar": false, "segurar_quando": null,
  "formulario": { "titulo": "Criar lançamento", "campos": [ … ] } }
```

Resposta (200), estorno (real, resumida): ganha `plano_ref` e o formulário traz `resumo` e `itens_estorno`:

```json
{ "tipo": "previa", "proposta": "8066d118-…", "plano_ref": "aed1faa405dc583777105073e3f67fb7",
  "risco": "exclusao", "segurar": true, "segurar_quando": null,
  "formulario": {
    "titulo": "Estornar a cobrança #1",
    "resumo": [ { "rotulo": "Estornar 1 × Consulta clínica", "valor": "R$ 150,00" }, { "rotulo": "Valor do estorno", "valor": "R$ 220,00" } ],
    "itens_estorno": [ { "item_id": 2, "descricao": "Vermífugo", "lancada": 2, "estornada": 0, "restante": 2, "preco": "R$ 35,00", "quantidade": 2 } ],
    "reautenticar": true, "tipo_autorizacao": "estorno" } }
```

Garantias da prévia (cobertas por `test_a_previa_nao_emite_token_nao_audita_nao_grava_e_ignora_segredos` e `test_a_previa_do_estorno_mostra_o_plano_sem_gravar_e_sem_ler_o_pin`): sem `token`, sem auditoria, sem gravar, sem tocar o rascunho, ignora `email_admin`, `senha_admin`, `pin`, `crmv` (inclusive dentro de `valores`).
- `plano_ref` só vem nas tools de estorno (`estornar_cobranca`, `estornar_venda`). É um hash de 32 hex; o front o trata como texto opaco.
- Sem permissão: 403 `{"tipo":"negado","codigo":"AI_FORBIDDEN","mensagem":"Seu perfil não permite esta ação."}` **(do código; sem auditar)**.
- Proposta inexistente/vencida: 422 `AI_PROPOSAL_UNAVAILABLE` ou `AI_PROPOSAL_EXPIRED` (mesmos formatos do Confirmar).

## 3. Confirmar — `POST /agente/confirmar`

Requisição (campos aceitos):

```json
{ "proposta": "uuid", "valores": { "campo": "valor" }, "plano_ref": "…", "email_admin": "…", "senha_admin": "…" }
```

- `valores`: opcional; só os campos do formulário. O servidor aplica por cima do rascunho. **Omita a chave quando não houver edição; nunca mande `null`** (`null` e texto → 422 `AI_VALIDATION_ERROR`; `{}` ou `[]` valem). O que o humano editou numa tentativa recusada **fica no rascunho** e vale nas tentativas seguintes.
- `plano_ref`: **opcional**. Mandar o da última prévia de estorno. Sem ele o servidor grava o plano recalculado no Confirmar (comportamento de antes).
- `email_admin` / `senha_admin`: **só quando `formulario.reautenticar` é `true`**. O significado muda com `formulario.tipo_autorizacao`: `estorno` = e-mail e PIN do supervisor/dono; `crmv` = CRMV e senha do próprio usuário; senão = e-mail e senha de um admin.

### 3.1 Sucesso — 200 (real)

```json
{ "tipo": "resultado_escrita", "tool": "criar_lancamento", "mensagem": "Lançamento criado.",
  "resultado": { "id": 1, "descricao": "Café", "valor": "33.00", "status": "pendente", "tenant_id": 1, "…": "…" } }
```

A proposta sai da sessão. Segurar não é exigido pelo servidor (só gesto visual).

### 3.2 Validação — 422 `AI_TOOL_REFUSED` (real)

Valores preservados, proposta continua em rascunho (pode corrigir e reenviar a mesma `proposta`). Auditado como `revisao_com_erro`.

```json
{ "tipo": "erro", "categoria": "validation_error", "codigo": "AI_TOOL_REFUSED", "http_status": 422,
  "mensagem": "Informe a descrição.", "erros": { "descricao": "Informe a descrição." },
  "proposta": "c7d81017-…", "risco": "escrita", "segurar": false, "segurar_quando": null,
  "formulario": { "campos": [ { "nome": "descricao", "faltando": true, "valor": null, "erro": "Informe a descrição." }, { "nome": "valor", "valor": "33" } ] } }
```

O que o humano digitou volta em `formulario.campos[].valor`; o erro de cada campo em `campos[].erro`.

### 3.3 Plano mudou — 422 `AI_PLAN_CHANGED` (real, só estorno com `plano_ref`)

Outro usuário estornou uma linha entre a prévia e o Confirmar. Nada gravado, proposta continua em rascunho, auditado como `revisao_com_erro`. Cuidado: o PIN **não** é gasto (a conferência vem antes).

```json
{ "tipo": "erro", "categoria": "validation_error", "codigo": "AI_PLAN_CHANGED", "http_status": 422,
  "mensagem": "O plano mudou desde a prévia. Revise de novo.", "proposta": "8066d118-…",
  "risco": "exclusao", "segurar": true, "segurar_quando": null,
  "plano_ref": "960bbe91c8ad1ca444e1dd49d7466ff3",
  "formulario": { "resumo": [ { "rotulo": "Valor do estorno", "valor": "R$ 185,00" }, { "rotulo": "Já estornado antes", "valor": "R$ 35,00" } ],
                  "itens_estorno": [ { "item_id": 2, "lancada": 2, "estornada": 1, "restante": 1 } ] } }
```

O front mostra o plano novo, troca o `plano_ref` pelo recebido aqui e o humano confirma de novo. **Reenvio verificado (teste e dump 13):** mesma `proposta`, `plano_ref` novo e credenciais, **sem** `valores`. Atenção: o formulário desta resposta volta com `modo: "itens"` (as linhas congeladas), enquanto a prévia mostrava `"tudo"`; reenviar `modo: itens` sem `linhas` **não foi verificado**, então não reenvie `valores` de estorno sem testar. Um `plano_ref` de tipo errado (ex.: array) também dá este 422 **nas tools de estorno**; nas demais tools (sem plano) o `plano_ref` é ignorado e a gravação segue normalmente (200).

### 3.4 Sem permissão — 403 (real)

```json
{ "tipo": "negado", "categoria": "authorization_error", "codigo": "AI_FORBIDDEN", "http_status": 403,
  "mensagem": "Você não tem permissão para executar esta ação." }
```

A proposta acaba (não adianta reenviar). Senha/PIN nem são conferidos nesse caso.

### 3.5 Autorização recusada — 403 / 429 (do código; os códigos e frases estão em `reautenticacaoRecusada`)

| Situação | Status | `codigo` | Observação |
|---|---|---|---|
| Sem e-mail/PIN/senha | 403 | `AI_REAUTH_REQUIRED` | `mensagem` fixa por tipo (estorno, crmv, admin) |
| Não conferiu | 403 | `AI_REAUTH_FAILED` | A proposta termina, abrir outro card |
| Tentativas demais | 429 | `AI_REAUTH_RATE_LIMIT` | **Código diferente do 429 do limiter** |

Formato: `{"tipo":"erro","categoria":"authorization_error"|"rate_limit","codigo":…,"http_status":…,"mensagem":…}`. Recusa de senha/PIN **encerra a proposta** (auditada como `negado`).

### 3.6 Proposta indisponível, vencida ou usada

- 422 `AI_PROPOSAL_UNAVAILABLE` (real): inexistente, de outra sessão, já concluída/cancelada/substituída. `"mensagem": "Esta proposta não está mais disponível. Nada foi gravado. Peça de novo."`
- 422 `AI_PROPOSAL_EXPIRED` (real): passou dos 5 min. `"mensagem": "O prazo para revisar terminou. Nada foi gravado. Peça de novo."`
- 409 (real): duplo clique no mesmo instante. `{"tipo":"erro","mensagem":"Esta confirmação já foi usada."}` (sem `codigo`). Em sequência real a segunda requisição costuma cair no 422 `AI_PROPOSAL_UNAVAILABLE`. **Cuidado:** esse 422 também sai para proposta cancelada, substituída ou de outra sessão, e a mensagem dele diz "Nada foi gravado". Quem diz se gravou é a primeira resposta; o front não deve afirmar "já foi processado" a partir do 422 — mostre a `mensagem` e, se a primeira resposta de sucesso já chegou, mantenha o sucesso.
- 422 `{"tipo":"erro","mensagem":"Confirmação fora do prazo. Refaça o comando."}` quando a proposta vence entre a leitura e a execução (raro; do código).

### 3.7 Limite — 429 `AI_RATE_LIMIT` (real)

30 pedidos por minuto por usuário (`agente-confirmar`). O 31º:

```json
{ "tipo": "erro", "categoria": "rate_limit", "codigo": "AI_RATE_LIMIT", "http_status": 429,
  "mensagem": "Muitos pedidos em pouco tempo. Aguarde um minuto." }
```

Não grava e não audita. Vem com os cabeçalhos do limiter (`Retry-After`, `X-RateLimit-*`): o `AppServiceProvider` repassa `$headers` na resposta (do código; o cabeçalho em si não foi inspecionado num teste).

## 4. O que o card envia e o que NUNCA envia

Envia: `proposta`; `valores` só com os campos do formulário (os editados, ou todos); `plano_ref` da última prévia de estorno; `email_admin`/`senha_admin` somente quando `formulario.reautenticar` for `true`.

Nunca envia (o servidor ignora ou recusa, mas não deve nem tentar):
- `tool`, `tenant_id`, `token`, ou qualquer id de tenant/empresa: o servidor usa o da sessão (`test_os_valores_editados_no_card_prevalecem_e_o_corpo_nao_escolhe_a_tool`).
- Preço, total ou `valor_centavos` de estorno/venda: o valor é sempre do servidor (preço copiado na linha × quantidade).
- `email_admin`, `senha_admin`, `senha`, `password`, `pin`, `crmv` **dentro de `valores`**: são removidos (lista `AgenteController::CHAVES_SECRETAS`); em estorno/cirurgia/lixeira definitiva essas credenciais vão nos campos de topo `email_admin`/`senha_admin`.
- Qualquer credencial na **prévia**: ignorada.
- Chaves extras dentro de `itens` da venda ou `linhas` do estorno: só `catalogo_item_id`/`quantidade` e `item_id`/`quantidade` são mantidas.

## 5. Checklist do B2

1. Na abertura do card usar `segurar` e `segurar_quando` (segurar 2 s só nas ações destrutivas).
2. Prévia com debounce em `POST /agente/revisar?previa=1`; guardar `plano_ref` quando vier; tratar 429 `AI_RATE_LIMIT` (30/min).
3. Confirmar com `{proposta, valores, plano_ref?, email_admin?, senha_admin?}`; um clique grava (ou o segurar nas destrutivas).
4. Tratar: 422 `AI_TOOL_REFUSED` (apontar campos), 422 `AI_PLAN_CHANGED` (plano novo + `plano_ref` novo, sem perder a proposta), 403 `AI_FORBIDDEN`, 403/429 `AI_REAUTH_*` (proposta encerrada), 409 e 422 `AI_PROPOSAL_UNAVAILABLE`/`EXPIRED` (refazer o comando), 429 `AI_RATE_LIMIT` (aguardar).
5. Não usar mais `/agente/editar` nem o `token` (continuam existindo só até a remoção).
